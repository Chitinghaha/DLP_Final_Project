# 2026-04-25 CIFAR-100 Sequential Incremental Ordered Pilot 紀錄

本日目標是建立一條新的 CIFAR-100 Sequential Incremental Ordered pilot 實驗線，用 `ResNet-18 / seed 1` 在正確的 incremental data flow 下比較 `Normal / Clustered / Interleaved` 三種 forget order。這次不是先追求完整 100-class 覆蓋，而是用 20-step animal subset 刻意放大 immediate forgetting lag，觀察連續遺忘時是否會出現「當步忘不乾淨，但後續可能逐步收斂」的現象。

## 1. 實驗目標

這次 CIFAR-100 pilot 的核心問題是：在單一類別遺忘方法大致有效的前提下，若改成 sequential incremental unlearning，是否會因為連續更新 shared representation / decision boundary 而出現 forgetting lag。

本次固定 failure / lag 判定為：

- Newly forgotten class 在當步 evaluation accuracy `> 10%`，視為 immediate forgetting lag / 遺忘失效訊號。
- 若後續 step 逐步下降到接近 `0%`，則解讀為短期 lag 後的 cumulative forgetting 收斂。
- 若多步後仍維持明顯高 accuracy，才視為更嚴重的 persistent forgetting failure。

## 2. Dataset 與 Data Flow 原則

本次實驗必須沿用目前 `sequential_incremental` 的正確資料流程，避免把舊 forgotten data 帶回後續訓練。這一點很重要，因為本次要觀察的是正確 incremental data flow 下的 lag，而不是舊資料重新進入 training 後造成的 recovery / relearning。

固定規則如下：

- `step k` 的 forget loader 只包含當步新的 forget class。
- Retain loader 只包含目前尚未被指定 forget 的 classes。
- 所有舊 forgotten classes 都要從後續 train loaders 永久排除。
- 舊 forgotten classes 只能出現在 evaluation 的 cumulative forgotten set。
- 後續觀察到的舊 class accuracy 變化，應解讀為 shared backbone / decision boundary 被後續 unlearning 間接影響，而不是該 class 被重新訓練。

## 3. CIFAR-100 Pilot Subset

Pilot 只選 20 個 CIFAR-100 fine classes，集中在高混淆的 animal 類別，分成 4 個 coarse groups：

- `large_carnivores`: `bear(3), leopard(42), lion(43), tiger(88), wolf(97)`
- `large_omnivores_and_herbivores`: `camel(15), cattle(19), chimpanzee(21), elephant(31), kangaroo(38)`
- `medium_mammals`: `fox(34), porcupine(63), possum(64), raccoon(66), skunk(75)`
- `small_mammals`: `hamster(36), mouse(50), rabbit(65), shrew(74), squirrel(80)`

三條 order 使用同一組 20 classes，只改 forget order，避免 subset 差異干擾 ordered comparison。

## 4. Ordered 設定

`Normal`

```text
3,15,19,21,31,34,36,38,42,43,50,63,64,65,66,74,75,80,88,97
```

`Clustered`

```text
3,42,43,88,97,15,19,21,31,38,34,63,64,66,75,36,50,65,74,80
```

`Interleaved`

```text
3,15,34,36,42,19,63,50,43,21,64,65,88,31,66,74,97,38,75,80
```

預期觀察方向：

- `Clustered` 會連續忘同一語義群，可能更容易在後續 step 間接補忘 lagged classes。
- `Interleaved` 在不同 animal group 間切換，可能讓 shared feature pressure 較分散，因此 lag 較容易拖長。
- `Normal` 作為固定順序 baseline，用來判斷這組 subset 是否在前段就容易出現 lag。

## 5. 執行策略

本次 queue 採單線、非平行、smoke-first 策略：

1. 檢查或訓練 CIFAR-100 baseline。
2. 依序跑三條 smoke test：`Normal k=2 -> Clustered k=2 -> Interleaved k=2`。
3. 任一 smoke failed 則停止，不進 full run。
4. Smoke 全通過後，依序跑 full pilot：`Normal k=20 -> Clustered k=20 -> Interleaved k=20`。
5. 任一 full run failed 則停止後續 full run，保留已完成結果與失敗 log。

本次為了盡量吃滿 GPU，batch size 已從原本較保守設定調整為：

```text
BATCH_SIZE=2048
```

目前 baseline training 期間 GPU utilization 已可達高使用率，因此暫時不再主動提高 batch size，避免因 memory 或 dataloader 壓力導致長時間實驗中斷。

## 6. Baseline Accuracy 比較

在目前的 `ResNet-18 / seed 1` 設定下，CIFAR-10 baseline 的 full test accuracy 為 `94.52%`，而 CIFAR-100 baseline 的 full test accuracy 為 `70.47%`；CIFAR-100 約低 `24.05` 個百分點，顯示其分類難度明顯更高。

這個差距符合預期：CIFAR-100 fine classes 更多、類別間語義更接近，尤其本次選的是 animal-heavy subset，本來就更容易產生 feature overlap 與 class confusion。因此 CIFAR-100 比 CIFAR-10 更適合拿來觀察 sequential unlearning 中的 forgetting lag。

目前不建議為了提高 CIFAR-100 baseline accuracy 中止並重訓，原因如下：

- 本次目標是 failure hunting / lag observation，不是追求最佳 CIFAR-100 SOTA accuracy。
- `70.47%` 對 ResNet-18 CIFAR-100 pilot 來說可作為合理起點。
- Pilot 20 個 animal classes 的 baseline average accuracy 約 `69.15%`，仍足以觀察 unlearning 是否從有效辨識能力下降。
- 若 baseline 太弱，確實會讓部分 class 的 forgetting interpretation 變模糊；但目前不是「低到無法分析」的狀態。

後續分析時需要額外檢查 lag 是否集中在 baseline 本來較低的 classes，避免把「原本就難分類」誤解成 unlearning failure。
